# 精密表面檢測工作流程

這份流程描述桌面程式目前能展示的離線檢測閉環：建立配方、校正尺度、單張確認、資料夾批次處理、匯出可追溯紀錄。它是通用作品內容，不綁定特定公司、產線或設備品牌。

## 1. 建立與凍結配方

JSON 配方包含：

- 傳統影像處理與 AI 的判定參數
- 料號、配方版本及可驗證的配方 SHA-256
- 傳統／AI／比較／融合模式
- 融合規則與人工複核條件
- 像素尺寸 `MicrometersPerPixel`
- 相機與光源設定檔的文字識別

內建值與 `recipes/precision-metal-starter.json` 都是離線驗證的起始點。正式使用時，應以料號、產品版本、鏡頭、工作距離、曝光、光源角度和演算法版本共同定義配方版號；本版尚未實作電子簽核與不可變更版號。

## 2. 校正像素尺度

使用已知尺寸的標定板，在實際工作距離與取像解析度下量測：

```text
MicrometersPerPixel = 標定物實際長度 (µm) / 影像中的量測長度 (px)
```

程式會把遮罩像素換算成平方毫米，並輸出瑕疵中心的 X／Y 毫米座標。若 AI 遮罩解析度不同，換算會先補償來源影像與遮罩的寬高比例。

注意：單一比例只適合畸變已受控且工件高度固定的平面場景。高精度量測仍需鏡頭畸變校正、視野多點驗證與量測系統分析（MSA）。

## 3. 融合判定

| 規則 | 兩方法一致 | 兩方法分歧 |
|---|---|---|
| 任一 NG 即 NG | 直接輸出共同結果 | NG，並標記需複核 |
| AI 主判、分歧複核 | 直接輸出共同結果 | 轉人工複核 |
| 一致才自動判定 | 直接輸出共同結果 | 轉人工複核 |

CSV 中的 `reason_code` 保留機器可讀原因，例如 `BOTH_OK`、`BOTH_NG` 或 `METHODS_DISAGREE`，避免只有畫面顏色而無法追查判定來源。

## 4. 批次檢測與追溯

先填寫批號／工單號，再按「資料夾批次」選擇影像資料夾及 CSV 儲存位置。預設會排除 `_GT`、`mask` 與 `label` 結尾的標註影像，也可選擇是否包含子資料夾。程式依相對路徑排序逐張執行，CSV 包含：

- 時間、批號、料號、檔名與來源相對路徑
- 來源影像 SHA-256
- 配方名稱、版本、SHA-256 與檢測模式
- 應用程式、傳統演算法與 AI pipeline 版本
- ONNX graph 與 external data 的 SHA-256
- 處理狀態、最終判定、複核旗標、原因代碼及錯誤訊息
- 像素校正值、相機與光源設定
- 傳統與 AI 的面積比例及 mm²
- 核心處理時間

CSV 在每張影像完成後立即寫入磁碟。單一影像無法解碼或檢測失敗時，該筆會記為 `Error`／`IMAGE_PROCESSING_ERROR`，整批繼續處理。按「停止」會在目前影像完成並寫入後終止；已完成項目會保留為部分 CSV。作業中關閉視窗也會走相同的安全停止流程。

只有當 NG、Error 與需複核數量全部為零時，批次總結才會顯示 `BATCH OK`。

## 5. 上線前仍需完成

- 以實際良品／不良品完成門檻驗證、GR&amp;R 或適用的 MSA
- 加入 ROI、相機畸變校正與量測標定記錄
- 串接工業相機觸發、PLC／機台握手及異常復歸
- 配方權限、版號、稽核軌跡、資料保存與備份策略
- 長時間壓力測試、模型漂移監控與誤判處置流程

目前成果適合展示「可操作、可量化、可追溯」的桌面原型；不宣稱已通過特定產線的量測或驗收標準。
